# LumaTherm 1.1.0 — проект релиза

Дата: 2026-08-22  
Статус: утверждено пользователем  
Целевая версия приложения: `1.1.0`  
Целевой репозиторий: `https://github.com/Spark0896/LumaTherm`

## 1. Цель

LumaTherm 1.1.0 превращает существующую рабочую версию 1.0.1 в публичное бесплатное open-source приложение для Windows 11. Приложение изменяет цвет совместимой RGB-подсветки по температуре NVIDIA GPU, продолжает управлять подсветкой в фоне и не требует GIGABYTE Control Center или MSI Afterburner для основного сценария.

Релиз должен:

- сохранить проверенное прямое управление через Windows Dynamic Lighting `LampArray`;
- получать температуру через NVIDIA NVML, используя MSI Afterburner shared memory только как необязательный резерв;
- поддерживать насыщенный плавный градиент с произвольным количеством температурных точек;
- предоставить русский и английский интерфейс;
- одинаково надёжно работать в открытом окне, в трее и при неактивном окне;
- поставляться установщиком и максимально функциональной portable-сборкой;
- проверять наличие обновлений через GitHub Releases;
- сопровождаться актуальной документацией для пользователей и разработчиков.

## 2. Границы и ограничения платформы

### 2.1 Поддерживаемая платформа

- Windows 11 версии 22H2 или новее (`10.0.22621.0+`).
- Архитектура x64.
- NVIDIA GPU и установленный драйвер с NVML для основного источника температуры.
- RGB-устройство, обнаруживаемое Windows как совместимый Dynamic Lighting `LampArray`.

Приложение является self-contained .NET 8 сборкой: отдельная установка .NET Runtime не требуется.

### 2.2 Независимость от сторонних RGB-программ

Основной путь подсветки использует только публичный Windows API `Windows.Devices.Lights.LampArray`. LumaTherm не вызывает GCC, не загружает закрытые DLL производителя и не выполняет неподдерживаемые raw HID-записи. GCC и другие контроллеры могут оставаться установленными, однако при конфликте пользователь должен поставить LumaTherm выше них в системном списке фонового динамического освещения.

### 2.3 Пакетная идентичность

Windows разрешает ambient/background-управление LampArray только процессу с пакетной идентичностью и расширением `com.microsoft.windows.lighting`. Поэтому основной установщик регистрирует лёгкую MSIX-идентичность. Portable-сборка содержит помощник для той же однократной регистрации. Без регистрации portable-приложение может запускаться, показывать интерфейс, читать температуру и тестировать доступные foreground-возможности, но не обещает приоритетное фоновое управление.

## 3. Архитектура

### 3.1 `LumaTherm.Core`

Core остаётся независимым от WPF, GitHub и Windows UI. Он отвечает за:

- модель температурного профиля;
- проверку и нормализацию температурных точек;
- HSV-интерполяцию насыщенных цветов с `smootherstep`-смягчением каждого сегмента;
- плавность перехода;
- контракт runtime и снимки состояния;
- модель пользовательских настроек.

Фиксированная трёхточечная модель заменяется упорядоченной коллекцией `ThermalPoint` с температурой и RGB-цветом. Количество точек не ограничивается искусственным максимумом. Валидный профиль содержит минимум две точки, температуры находятся в диапазоне 0–120°C и возрастают минимум на 1°C.

Профиль по умолчанию содержит три точки: 35°C `#006BFF`, 65°C `#D000FF` и 85°C `#FF0000`. Между соседними точками цвет рассчитывается независимо, а `smootherstep` обеспечивает нулевую скорость изменения на границах сегмента: соседние целые температуры возле точки не создают заметного скачка на физических светодиодах. Добавление точки локально изменяет только два соседних отрезка.

### 3.2 `LumaTherm.Infrastructure`

Infrastructure сохраняет существующие адаптеры:

- NVML — основной источник температуры;
- MSI Afterburner shared memory — необязательный read-only fallback;
- Windows LampArray — единственный путь записи RGB;
- JSON — сохранение настроек;
- Windows startup/package APIs — автозапуск и пакетная идентичность.

Добавляются:

- миграция схемы настроек 1.0.1 в новую многоточечную схему;
- клиент проверки последнего стабильного релиза GitHub;
- сервис открытия доверенных HTTPS-ссылок;
- сведения о текущей версии и типе установки.

Проверка обновлений выполняется только по явному действию пользователя. Сбой сети, ограничение GitHub API или неверный ответ отображаются на странице «О программе» и не влияют на runtime подсветки.

### 3.3 `LumaTherm.App`

WPF-приложение сохраняет MVVM и существующую дизайн-систему. Новые представления:

- страница «О программе»;
- интерактивный редактор температурной шкалы;
- модальное окно теста подсветки;
- элементы локализации и выбора языка;
- настройки состава меню трея.

Строки интерфейса не хранятся в ViewModel как русские литералы. Они берутся из ресурсов RU/EN через единый сервис локализации. Выбор `Системный / Русский / English` применяется ко всему UI и сохраняется. В системном режиме используется язык Windows; для неподдерживаемого языка применяется английский.

## 4. Интерактивная температурная шкала

Редактор отображает итоговый градиент и цветные круглые маркеры всех точек.

- Перетаскивание маркера изменяет температуру в реальном времени.
- Точки автоматически упорядочиваются.
- Маркер не может пересечь соседа; минимальный интервал — 1°C.
- Щелчок выбирает точку и открывает точные поля температуры и цвета.
- Новая точка добавляется кнопкой `+` или двойным щелчком по полосе.
- Цвет новой точки вычисляется из текущего градиента в выбранной температуре, поэтому добавление само по себе не создаёт скачка цвета.
- Выбранную точку можно удалить кнопкой или клавишей `Delete`, пока после удаления остаётся минимум две точки.
- Крайние точки редактируются наравне с остальными.
- Клавиатурное управление и понятные AutomationProperties обязательны.

Редактор используется как один переиспользуемый компонент в настройках и окне тестирования, чтобы поведение не расходилось.

## 5. Тест подсветки

Кнопка «Проверить подсветку» находится непосредственно в карточке цветовой шкалы и открывает стилизованное окно в текущей тёмной теме LumaTherm. В окне находятся:

- интерактивная температурная шкала;
- ползунок тестовой температуры;
- числовое значение температуры;
- крупный образец рассчитанного цвета;
- редактор выбранной точки;
- явные действия «Применить» и «Отмена/Закрыть».

При активном аппаратном тесте реальная температура временно не используется для выбора цвета, однако считывание датчика продолжается. Закрытие окна, отмена, исключение или завершение приложения обязаны снять тестовое переопределение и восстановить прежний runtime-режим. Если основной режим был выключен, тест может временно получить управление подсветкой только после явного действия пользователя и после закрытия снова освобождает устройство.

Изменения профиля в тестовом окне являются черновиком до нажатия «Применить». Это предотвращает случайное сохранение множества промежуточных значений во время перетаскивания.

## 6. Сохранение состояния

Настройки профиля и поведения сохраняются отдельно от оперативного переключения терморежима.

Текущая ошибка 1.0.1 возникает потому, что SettingsViewModel сохраняет устаревшую копию `IsModeEnabled`. В 1.1.0 runtime предоставляет отдельную операцию сохранения пользовательских предпочтений, которая атомарно сохраняет профиль и поведение с актуальным runtime-флагом. Включение режима остаётся отдельной операцией. В результате сохранение цветов, температур, языка, трея или автозапуска не включает и не выключает режим.

Схема настроек повышается. Миграция преобразует старые `cold/warm/hot` значения в три `ThermalPoint`, сохраняя температуры, цвета, сглаживание, автозапуск, уведомления, выбранное устройство и текущий статус режима. При автозапуске сохранённый статус режима восстанавливается даже после перезагрузки Windows; маркер незавершённой предыдущей сессии показывает предупреждение, но не переписывает пользовательский выбор. Неизвестная будущая схема не перезаписывается молча; приложение сообщает о несовместимости и использует безопасные значения в памяти.

## 7. Трей

Меню трея формируется из типизированных команд, а не из массива позиций. Это позволяет скрывать элементы без нарушения обработчиков.

Настраиваемые элементы:

- текущая температура GPU;
- «Открыть LumaTherm»;
- «Включить/выключить режим».

«Выход» всегда отображается. Температура и подписи обновляются из текущего runtime snapshot. Предпросмотр в настройках использует те же ViewModel и локализованные данные, поэтому статическое `68°C` удаляется. Все команды предпросмотра используют контрастный основной цвет текста на тёмной поверхности. Смена языка обновляет реальное меню и предпросмотр.

## 8. Страница «О программе» и обновления

Страница по кнопке `i` содержит:

- логотип и название LumaTherm;
- краткое описание;
- текущую версию `1.1.0`;
- указание, что программа бесплатная и open source;
- лицензию MIT;
- ссылку `https://github.com/Spark0896/LumaTherm`;
- кнопку ручной проверки обновлений;
- состояние проверки и ссылку на новый GitHub Release при его наличии.

Проверка использует endpoint последнего стабильного GitHub Release, HTTPS, ограниченный размер ответа и короткий timeout. Pre-release и draft-релизы не предлагаются обычным пользователям. Версии сравниваются как SemVer. Приложение не скачивает и не запускает файлы скрытно: пользователь переходит на страницу релиза, где видит описание и артефакты.

## 9. Визуальная система

Текущий тёмный интерфейс, логотип, размеры, отступы, скругления и голубые акценты сохраняются. Новые окна и контролы используют общие ресурсы приложения.

`SectionHeadingStyle` и аналогичные стили явно задают светлый `PrimaryTextBrush`, чтобы заголовки карточек не наследовали чёрный цвет из системных шаблонов. Контраст проверяется для RU и EN, включая длинные английские подписи и масштабирование Windows.

Системные диалоги применяются только там, где это ожидаемо пользователем (например, выбор цвета при необходимости). Основные сценарии теста, обновлений и информации об app остаются внутри визуального языка LumaTherm.

## 10. Установщик и portable

### 10.1 Основной установщик

Основной артефакт — self-contained x64 установщик Inno Setup со sparse MSIX identity. Inno Setup используется только для сборки установщика и не требуется на компьютере пользователя. Установщик предлагает:

- выбор каталога установки;
- галочку создания ярлыка на рабочем столе;
- галочку создания ярлыка в меню Пуск;
- безопасное обновление существующей установки;
- запуск после установки;
- полноценное удаление файлов, ярлыков и принадлежащей LumaTherm регистрации.

Для бесплатного релиза пакет подписывается выделенным self-signed сертификатом проекта. Установщик проверяет соответствие сертификата подписи и контрольные суммы, запрашивает UAC и импортирует только публичный сертификат в необходимое системное хранилище. Приватный ключ никогда не входит в релиз. Документация честно объясняет этот шаг. В будущем подпись можно заменить Azure Artifact Signing, доверенным OV-сертификатом или Microsoft Store без изменения runtime-архитектуры.

### 10.2 Portable

Portable ZIP содержит те же self-contained бинарники, документацию и помощник `Register-LumaTherm.ps1` для регистрации sparse identity в текущем расположении. Приложение показывает предложение запустить этот помощник, если identity отсутствует. После регистрации portable-версия функционально соответствует установленной, пока папка не перемещена. При перемещении приложение обнаруживает несовпадение external location и предлагает перерегистрировать идентичность.

Запуск без регистрации допускается, но UI явно сообщает, что Windows может отобрать подсветку после потери фокуса. Portable не называет такой режим полностью поддерживаемым фоновым сценарием.

## 11. Автозапуск и обновление установки

Автозапуск по умолчанию выключен. Для установленной и зарегистрированной portable-версии используется стабильный путь к реальному исполняемому файлу и один механизм, совместимый с выбранной пакетной идентичностью. Переключатель отображает фактическое системное состояние, а не только сохранённый JSON. Скрытый запуск не изменяет `IsModeEnabled`: ранее включённый терморежим возобновляется автоматически, а ранее выключенный остаётся выключенным.

Обновление поверх предыдущей версии сохраняет пользовательские настройки. Удаление не обязано удалять настройки автоматически; установщик предлагает отдельный явный выбор очистки пользовательских данных.

## 12. Ошибки и восстановление

- Потеря GPU-датчика переводит runtime в понятное состояние ожидания и сохраняет последний цвет только в рамках существующей безопасной политики.
- Потеря LampArray освобождает сессию, показывает статус и периодически повторяет обнаружение без busy loop.
- Ошибка тестового режима всегда приводит к снятию override в `finally`.
- Ошибка автозапуска откатывает только изменение автозапуска и не изменяет терморежим.
- Ошибка локализации использует английский fallback.
- Ошибка GitHub остаётся локальной для страницы обновлений.
- Все внешние ссылки ограничены заранее известным HTTPS-хостом GitHub.

## 13. Проверка качества

Разработка каждого изменения идёт через failing test → минимальная реализация → refactor.

Обязательные автоматические проверки:

- интерполяция произвольного количества точек и граничные температуры;
- насыщенность и непрерывность реального LED-градиента;
- добавление, удаление, сортировка и перемещение точек;
- миграция настроек 1.0.1 и round-trip новой схемы;
- сохранение настроек без изменения runtime-режима;
- lifecycle тестового override;
- локализация всех ViewModel, трея и страницы About;
- разбор SemVer и ответов GitHub Releases;
- скрытие разрешённых пунктов трея при обязательном «Выход»;
- установщик, sparse identity, portable-регистрация, обновление и удаление;
- отсутствие захардкоженного `68°C` и явный foreground заголовков.

Перед релизом выполняются:

- полный `dotnet test` и Release build без предупреждений;
- проверка installer и portable на чистом профиле Windows;
- запуск, сворачивание, закрытие в трей и работа при неактивном окне;
- автозапуск после входа;
- реальный тест LampArray по температурному ползунку;
- проверка восстановления после сна и потери устройства;
- визуальная проверка RU/EN и актуальные скриншоты;
- проверка SHA-256 всех релизных файлов.

## 15. GitHub и выпуск

После завершения кода, документации и проверок создаётся публичный репозиторий `Spark0896/LumaTherm`. До этого внешняя публикация не выполняется.

Репозиторий получает описание на английском, темы `windows`, `dynamic-lighting`, `rgb`, `gpu-temperature`, `wpf`, `dotnet`, `open-source`, скриншоты, исходники и воспроизводимые инструкции сборки.

GitHub Release `v1.1.0` публикуется только после финальной аппаратной проверки. В release notes перечисляются функции, требования, известные ограничения portable-режима, инструкция установки и SHA-256. Артефакты включают основной установщик, portable ZIP и `SHA256SUMS.txt`.

## 16. Критерии готовности

Релиз 1.1.0 готов, когда одновременно выполнено следующее:

1. Все автоматические тесты проходят, сборка не содержит предупреждений.
2. Сохранение настроек не меняет активность терморежима.
3. Фоновая подсветка сохраняется после сворачивания и потери фокуса.
4. Автозапуск восстанавливает последний сохранённый статус терморежима.
5. Интерактивная шкала поддерживает три точки по умолчанию и произвольное количество пользовательских точек.
6. Тестовая температура управляет реальными светодиодами и корректно восстанавливает runtime.
7. Русский и английский интерфейсы полностью проверены.

## Исправленные дефекты

### 1. Исключение одного датчика блокировало резервный источник — P2

**Место:** `src/LumaTherm.Core/Sensors/TemperatureProvider.cs`.

При исключении первого источника цикл чтения прерывался, даже если следующий
источник мог вернуть температуру. Теперь сбой отдельного источника позволяет
перейти к следующему; отмена вызывающей стороны продолжает распространяться.
Проверка воспроизводит отказ NVML и доступность резервного источника.

### 2. Ошибка освобождения источника прерывала остальную очистку — P2

**Место:** `src/LumaTherm.Core/Sensors/TemperatureProvider.cs`.

Если первый `DisposeAsync` выбрасывал исключение, остальные источники не
освобождались. Теперь предпринимаются все попытки очистки; одиночная ошибка
передаётся с исходным стеком, несколько ошибок объединяются. Регрессия
проверяет освобождение второго источника при ошибке первого.

### 3. JSON-алиасы профиля обходили канонические точки — P2

**Место:** `src/LumaTherm.Core/Colors/ThermalProfile.cs`.

В schema 2 десериализатор сначала создавал профиль из `Points`, затем мог
повторно применить `ColdTemperature`, `HotColor` и другие производные
свойства. Противоречивые значения перезаписывали точки; пустой массив с
такими свойствами вызывал `IndexOutOfRangeException` до штатной валидации.

Производные свойства исключены из JSON. В schema 2 каноничны `Points` и
`SmoothingSeconds`; миграции schema 0/1 продолжают явно читать старые поля.
Проверены противоречивые алиасы, пустые точки, обычное сохранение/загрузка
и интеграционное восстановление повреждённого файла.

### 4. HEX-парсер принимал пять цифр с пробелом как шесть цифр — P3

**Место:** `src/LumaTherm.Core/Colors/RgbColor.cs`.

`NumberStyles.HexNumber` допускает окружающие пробелы. Поэтому строки
`" FFFFF"`, `"FFFFF "`, `"# FFFFF"` проходили проверку длины и меняли цвет.
Теперь допустимы ровно шесть HEX-цифр с необязательным `#`. Отдельная
нормализация пользовательского ввода в ColorPicker сохраняется.

### 5. Неверный тип JSON-поля срывал запуск вместо восстановления — P2

**Место:** `src/LumaTherm.Infrastructure/Settings/SettingsMigrator.cs`.

Например, `{"schemaVersion":"2"}` или строковая legacy-температура
вызывали `InvalidOperationException` внутри `JsonElement.TryGetInt32` /
`TryGetDouble`. Теперь тип проверяется до преобразования; повреждённые
настройки попадают в существующий карантин и восстановление.

### 6. Временная ошибка чтения приводила к сбросу исправных настроек — P2

**Место:** `src/LumaTherm.Infrastructure/Settings/JsonSettingsStore.cs`.

Любой `IOException` считался повреждением JSON. Файл, временно закрытый
другим процессом для чтения, но разрешённый к переименованию, переносился
в карантин, а приложение переходило на значения восстановления.
Теперь произвольная ошибка ввода-вывода передаётся вызывающему коду;
исходный файл остаётся на месте. Подтверждено удержанием реального временного
файла с `FileShare.Delete` и проверкой сохранности его байтов.

### 7. Зависшая shared memory Afterburner считалась свежим измерением — P2

**Место:** `src/LumaTherm.Infrastructure/Sensors/AfterburnerTemperatureSource.cs`.

Источник игнорировал время последнего опроса производителя и присваивал
каждому чтению текущее время. Замороженное значение могло бесконечно
поддерживать обычный режим вместо обнаружения потери датчика.

Формат сверён с локальным официальным SDK MSI
`SDK/Include/MAHMSharedMemory.h`: signed Unix `time32` в смещении 20.
Источник отклоняет нулевое, отрицательное, будущее и более старое, чем
5 секунд, время. В принятом измерении сохраняется время производителя.
После отказа источника действует обычная политика удержания runtime;
5 секунд свежести источника и последующее удержание runtime — разные этапы.
Предполагаются часы одного ПК и секундная точность заголовка MAHM v2.

### 8. Отключение LampArray могло сорвать уведомление об устройствах — P2

**Место:** `src/LumaTherm.Infrastructure/Lighting/LampArrayLightingController.cs`.

Если native `Disable()` уже удалённого устройства выбрасывал исключение,
оно выходило из callback, и `DevicesChanged` не доставлялся. Соединение
теперь очищается, ошибка такого отключения перехватывается, уведомление
доставляется. Проверено подставным устройством с отказом `Disable()`.

### 9. Незавершённое IPC-сообщение навсегда занимало activation pipe — P2

**Место:** `src/LumaTherm.Infrastructure/System/SingleInstanceCoordinator.cs`.

Один клиент текущего пользователя мог подключиться, отправить часть `SHOW`
без перевода строки и удерживать единственное соединение. Последующие
запуски не могли активировать окно. Для чтения одного клиента добавлен
тайм-аут 1 секунда; его истечение не останавливает listener. Регрессия
удерживает неполного клиента и проверяет успешную следующую активацию.

### 10. Повторный запуск во время hidden startup терял активацию — P2

**Место:** `src/LumaTherm.App/Composition/AppHost.cs`.

Сигнал второго экземпляра до создания `_ui` отбрасывался. Второй процесс
завершался, а первый оставался скрытым. Активация теперь сохраняется и
выполняется после создания интерфейса; остановка приложения имеет приоритет.
Регрессия блокирует загрузку настроек и отправляет сигнал в этот промежуток.

### 11. Ошибка открытия браузера завершала всё приложение — P2

**Место:** `src/LumaTherm.App/ViewModels/AboutViewModel.cs`, RU/EN resources.

Ошибка системного обработчика ссылок, например `Win32Exception`, выходила
из синхронной команды в глобальную границу исключений, которая завершает
приложение. Теперь показывается локализованное сообщение с возможностью
повторной попытки. Доступный релиз и состояние проверки обновления сохраняются.

### 12. Release-сборка зависела от игнорируемого локального SDK — P2

**Место:** `scripts/build-release.ps1`.

Скрипт требовал `.dotnet/dotnet.exe`, хотя документация разрешала обычный
установленный SDK. Чистый клон с необходимым SDK в PATH не мог собрать
релиз по инструкции. Теперь приоритет имеет SDK репозитория, затем
`dotnet.exe` из PATH. Команды выполняются из корня решения, чтобы выбор
SDK по `global.json` не зависел от текущей папки запуска. Проверены обе
ветви поиска; Full/signing при ревью не запускались.

### 13. Smoke simulate принимал нечисловую длительность — P2

**Место:** `tools/LumaTherm.Smoke/SmokeCommand.cs`.

`--seconds NaN` проходил проверки диапазона и приводил к ошибке уже после
входа в сценарий управления подсветкой. Теперь длительность проверяется
на конечность до обращения к контроллеру. Проверка подтверждает ошибку
валидации и отсутствие подключения к устройству.

### 14. Установка могла зарегистрировать приложение для другой учётной записи — P2

**Место:** `packaging/LumaTherm.Consent.iss`,
`scripts/Resolve-LumaThermInstallerConsent.ps1`.

Sparse AppX registration и HKCU-настройки выполняются для текущего пользователя
повышенного процесса. Если стандартный пользователь вводил данные другой
администраторской учётной записи, setup мог сообщить успех, а приложение
запускалось без нужной регистрации у исходного пользователя.

Добавлена предварительная проверка: исходный, неповышенный токен должен
иметь тот же SID, что и повышенный установщик. При несовпадении либо
невозможности проверки setup останавливается до замены файлов и импорта
сертификата. Поскольку Inno не может восстановить исходный токен у уже
повышенного запуска, такой запуск теперь отклоняется явно. Поддерживаемый
путь — обычный запуск setup из нужной администраторской учётной записи
с последующим подтверждением UAC тем же пользователем.

Это намеренное ограничение: прямой «Запуск от имени администратора»,
изначально повышенная консоль, полнотокенные сеансы с отключённым UAC и
развёртывание от SYSTEM не поддерживаются этим установщиком.
`/ALLOWCERTIMPORT` разрешает импорт сертификата и не обходит проверку
учётной записи. Переработка установки на отдельные machine/user этапы
в данное исправление не входит.

Проверяются реальные read-only команды сравнения SID/токена и совпадение
сгенерированного include. Из-за недоступного компилятора полная компиляция
Inno и фактическая обработка UAC остаются отдельной непроверенной границей.

## Документация, доставка и ограничения

### Дополнительные установочные проверки

- В `scripts/Register-LumaTherm.cmd` жёсткое `C:\Windows` заменено на
  `%SystemRoot%`, чтобы Windows на другом томе не ломала регистрацию.
  Сценарий проверен чтением; пробное выполнение cmd с echo-подстановкой
  отклонено автоматической проверкой разрешений (`blocked by policy`)
  до запуска. Фактическое выполнение этого wrapper не подтверждено.
- В `[Setup]` файла `packaging/LumaTherm.iss` добавлено
  `MinVersion=10.0.22621`, согласованное с WPF project и sparse manifest.
  Ранее setup мог заменить файлы на неподдерживаемой Windows и лишь
  затем получить отказ AppX registration. Проверка версии теперь
  заявлена до установки; фактический запуск на старой ОС не выполнялся.

Текущие инструкции приводятся в соответствие с реализацией:

- Свежая установка включает режим и автозапуск (`FirstRun`); после
  повреждения настроек используются безопасные отключённые значения
  (`Default`). Это разные сценарии.
- Карантин предназначен для повреждённых данных, а не временных ошибок
  чтения. JSON schema 2 хранит точки профиля без производных алиасов.
- Windows LampArray может быть обнаружен, но временно недоступен из-за
  arbitration. `LightingWaiting` отличается от отсутствия устройства.
- Резервный источник Afterburner требует обновления producer timestamp;
  возраст более 5 секунд считается потерей измерения.
- Свободное число точек ограничено допустимым диапазоном 0–120 °C и
  минимальным шагом 1 °C: максимум 121 точка.
- `SECURITY.md` исправляет хранилище сертификата на фактически используемое
  `LocalMachine\Root` вместо `LocalMachine\TrustedPeople`.
- Описаны выбор SDK и ограничение учётной записи при установке.

Исторические QA-записи и планы сохраняются как свидетельства своего
времени; актуальные правила находятся в пользовательской документации
и исходниках.

## Непроверенные эксплуатационные границы

Проверялись изменённые исходники после опубликованной версии 1.2.0.
Запись `[Unreleased]` отделяет их от ранее опубликованных бинарников:
новая проверка учётной записи не приписывается старому установщику.

- Реальная перезагрузка, Windows logon, sleep/resume, длительное владение
  LampArray и физическое отключение устройства.
- Реальная установка/удаление, alternate-credential UAC и доверие сертификату
  на чистом пользовательском ПК.
- DPI, touch, расположение трея и визуальная приёмка изменённой сборки.
- Производственный NVML/Afterburner и реальные светодиоды: тесты используют
  подставные API, собственные memory maps, pipes и временные файлы.

Глобальные настройки Dynamic Lighting, службы, драйверы, сертификаты,
реестр и установленная LumaTherm в ходе этого ревью не изменялись.
Обнаруженный LampArray в состоянии `LightingWaiting` остаётся отдельным
ограничением Windows arbitration; ревью не выдаёт исправления runtime
за доказанное получение управления подсветкой после загрузки ОС.
